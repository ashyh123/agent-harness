# 博客 → 共同概念 → 其他博客

博客保存后，把已保存摘要和短引文交给同一个 DeepSeek 模型建议概念，再由程序建立 Obsidian 内部链接。第一版只使用六个维护好的概念：工具调用、执行环境、会话持久化、后台任务、MCP集成、Agent编排。不让模型任意新增同义节点，也不推断文章之间支持、冲突或采用相同方案。

## 使用

在项目根目录配置 `.env`，进入 `vercel_agent`：

```sh
# 保存、回读核验成功后，CLI自动整理共同概念
npm run blog -- "https://博客地址"
npm run blog:agent -- "https://博客地址"

# 为已有阅读笔记补建关联，或单独重试整理
npm run blog:index -- "/absolute/path/to/阅读笔记.md" "/absolute/path/to/另一篇.md"
```

`MINIMAL_AGENT_OBSIDIAN_VAULT` 设置专属 vault，默认 `~/Documents/Obsidian/Agent 博客阅读`。单独整理仅接受当前保存工具生成的笔记格式；不扫描个人 vault 的其他笔记。通用 Harness、person、验证程序及直接调用 BlogWorkflow.run 不隐式触发整理；它们生成的笔记可以交给 `blog:index`。

```text
Agent 博客阅读/
  阅读笔记/              原摘要、引文、来源；不改写
  提取原文/              原文快照；不改写
  知识图谱/
    首页.md
    文章/<稳定来源名>.md  一篇来源一个节点，连接所有分析版本及共同概念
    概念/工具调用.md      概念定义、英文别名、相关博客链接
    概念/执行环境.md
    ...
    .index.json          来源身份、版本哈希、分类规则哈希、自动区哈希
```

文章节点使用标准化 URL 的 SHA-256 作为身份，忽略 `#` 段落锚点、保留查询参数。改变摘要、标题不会再产生一个文章节点；原阅读笔记仍保留各自版本。不承诺合并 URL 重定向、跟踪参数或同一内容的不同域名。

## 在 Obsidian 查看

1. 打开专属 vault 的 `知识图谱/首页.md`，点击一篇文章。
2. 打开这篇文章的**局部关系图**，深度设为 **2**，即可查看“博客 → 概念 → 其他博客”。
3. 全局关系图搜索 `path:"知识图谱"`，减少原文和分析版本节点的干扰。添加颜色分组：`path:"知识图谱/文章"`、`path:"知识图谱/概念"`。

无需插件或图数据库。Markdown 的 `[[内部链接]]` 形成边；属性保存节点类型、来源与概念列表；`aliases` 记录概念的英文名称。没有自动修改个人 Obsidian 配置。

## 检查与保护

- 模型返回0–4个目录内的概念，每个附关联原因、依据字段和逐字片段。证据不足可以不关联。
- 程序拒绝未知/重复概念、过长或虚构片段；片段必须在已保存摘要或引文中，且含该概念的必要关键词。例如只有SDK或内置工具不能建立MCP关联。这是筛选门槛，不能独立证明语义归类正确。
- 节点展示关联原因及依据，明确标记“已保存摘要”或“原文引文”。不把个人启发当原文事实，也不声称模型重新阅读了全文。
- 重跑相同笔记使用哈希缓存，不再请求模型；修改笔记或分类规则时重新分类。
- 原阅读笔记和原文快照不改写。图谱每个文件末尾有“用户补充”标记，标记后的手写内容会保留；修改自动生成部分则停止并报错，不覆盖。
- 拒绝越出vault、符号链接、无关同名文件；单个文件临时写入后重命名，有锁防止本索引器并发。多文件不是整体事务；异常中断可能需要人工检查索引、自动文件或残留锁，不能保证自动恢复。

整理是保存后的独立阶段，最多一次模型请求、30秒API执行预算、最多1024输出tokens（不超过当前模型配置）。它有额外用量，CLI单独打印，不混入原博客保存基准。固定工作流最近运行记录增加 `indexing` 及整体耗时。整理失败仍保留已通过验收的原笔记，可单独重试；失败API可能产生用量，目前不持久化该阶段失败时的完整usage。

## 本机验收（2026-10-11）

使用此前通过博客内容验收的 Anthropic、OpenAI、Google 三篇文章，每篇两份分析版本，实际写入同一 Obsidian vault：

- 形成3个稳定文章节点、6个概念节点、6份原分析版本；内部链接实际检查可解析，原笔记SHA-256保持不变。
- 人工核对发现初版将OpenAI内置工具误归为MCP；加入必要关键词限制并使分类缓存失效后，重新整理六份笔记，OpenAI仅关联工具调用和Agent编排。
- 最终规则整理6次模型请求，共5195tokens，约11.98秒（含CLI与子进程启动）；此前初版探索另消耗4377tokens，不能从总实验成本中扣除。
- 重复整理同样笔记0次模型请求、0tokens；不代表新增笔记没有成本。
- 离线测试验证链接可解析、同源版本合并、跨文章共同概念、缓存及规则变更、原笔记保留、用户补充保留、自动区冲突拒绝、错误依据与路径拒绝。

这些是共同主题建议的工程验收，并未证明任意文章的语义关联都正确，也不改变原博客摘要的阅读范围。

代码入口：`obsidian_knowledge_cli.ts`；分类与写入：`obsidian_knowledge.ts`；CLI集成：`blog_workflow_cli.ts`、`blog_agent_cli.ts`；测试：`tests/obsidian_knowledge.test.ts`。

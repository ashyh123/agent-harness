# OMP 与原 Harness：博客阅读、Obsidian 保存和概念关联

2026-10-12，本机 OMP 18.9.2 的实际配对试验。结论：在当前模型、业务工具和小预算下，没有观察到 OMP 自主循环能稳定改善这个任务。建议采用 OMP 的交互与会话能力，常规收录继续调用已经验收的固定工作流。

## 比较了什么

- 原方案：`BlogAgent → MinimalHarness → LangGraphLoop`，不是早期手写循环，也不是当前默认的固定 BlogWorkflow。
- OMP：实际启动 OMP CLI，让其原生模型/工具循环选择四个工具。扩展只接线，不在内部调用原 Harness 或 BlogWorkflow。
- 四个共享工具：`read_webpage`、`read_saved_webpage`、`search_saved_webpage`、`save_obsidian_blog`。
- 相同 Skill、系统策略、DeepSeek `deepseek-flash`、temperature=0、每次输出512tokens；thinking关闭。
- 相同Python预算与参数校验、保存前证据核对、真实保存收据、保存通过即停止的规则。证据核对调用计入循环成本。
- 相同保存后 `ObsidianKnowledge`，额外最多一次模型请求、30秒、512输出tokens；成功及失败均单独计量。
- 用上次冻结的 Anthropic / OpenAI / Google 三篇真实厂商博客，每篇每组两次，两批共每组12次。不是实时网页抓取可靠性测试，也不是完整长文章通读测试。
- 顺序交替、独立上下文和真实Obsidian子vault。不覆盖日常笔记，不修改用户OMP主配置。

任务限定为“阅读实际提供的范围、简化核心内容、带直接支持的短引文、标记个人推论、真实保存、共同概念关联”。不含Jev分类、person路由、Codex委派、浏览器自动化或定时任务。

## 预算边界

沿用原配置：`max_steps=5`、`max_model_requests=8`、工具尝试8次、循环90秒。旧桥接的 `begin_model` 同时把证据核对和压缩算进外层5次计数，实际会先触发5次模型请求限制。这是当前实现的有效约束，不等于有8次可用的普通模型调用。两边完全共用这一计数。

原方案保留既有legacy上下文策略；OMP使用soft压缩、12000tokens阈值、近期保留2000tokens，关闭异步压缩和模型切换。估算器、压缩实现、截断恢复及工具错误呈现不同，因此这是执行方案比较，不能把结果归因于循环调度器单一变量。

## 两批合并结果

以下均值覆盖所有尝试，包含失败，不能把失败时较早停止当作效率优势。

| 指标 | 原LangGraph Harness | OMP |
|---|---:|---:|
| 尝试数 | 12 | 12 |
| 博客保存及文件核验通过 | 7/12（58.3%） | 7/12（58.3%） |
| 博客和图谱程序闭环 | 4/12（33.3%） | 4/12（33.3%） |
| 严格任务验收：另需人工内容/概念复核通过 | 3/12（25.0%） | 2/12（16.7%） |
| 已保存笔记中人工判定无需修订 | 3/7 | 3/7 |
| 每次循环平均tokens，含证据核对 | 17,063.6 | 18,077.7 |
| 每次循环平均耗时 | 6.82秒 | 7.16秒 |
| 平均循环模型请求 | 4.25 | 4.42 |
| 平均工具尝试，含参数拒绝 | 3.17 | 3.33 |

本样本OMP的循环tokens约多5.9%，耗时约多5.0%。两批方向不同：第一批原方案循环均值15801.5tokens、OMP18981.7；第二批原方案18325.7、OMP17173.7。图谱闭环第一批3:1、第二批1:3。小样本、temperature=0下仍有变动，不能据此宣布某一框架普遍更强。

“严格任务验收”采用保守的人工原文对照，评审者知道执行组，不是盲评或客观统计金标准；重要范围歧义也判为需要修订。核心结论成立但次要条件需要澄清，并不表示整篇均错。逐条理由保存在本机quality-review.json，不把预保存核对模型的通过结论当作独立内容验收。

## 完整流程用量

第二批已捕获索引失败时的API usage，包含循环、证据核对、成功和失败的概念整理：

| 每次尝试平均值，各6次 | 原Harness | OMP |
|---|---:|---:|
| 完整流程tokens | 18,985.5 | 17,767.3 |
| 完整流程耗时 | 8.28秒 | 7.84秒 |

不能单独挑这一批宣布OMP更省。第一批OMP两次索引失败未捕获其额外usage，不能将未知费用算成0，也不能给两批合并的完整流程精确token数。两批循环usage均完整。连接试跑另消耗22516tokens，未混入正式样本，但也是实际实验成本。

统计使用DeepSeek实际 `usage.total_tokens`；输入中已包含cache-hit tokens，未再重复相加。缓存未强制冷启动，不能由tokens直接推断金额。OMP本机测试provider的价格元数据设为0是占位，并不表示API免费。

## 失败原因与内容复核

1. 原Harness部分任务在旧上下文维护中，剩余模型预算不足以完成压缩并继续；OMP部分任务因超长引文、证据核对拒绝及回查修正耗尽5次模型预算。
2. 两边均出现保存成功但概念整理失败。共享索引器会拒绝重复/未知概念、片段不在指定字段或未含概念必要词的结果，当前错误提示未细分原因。框架返回结束不能代表图谱已完成。
3. Anthropic笔记的接口解耦引文确实支持核心机制，但部分摘要把“令牌无法被生成代码访问”加强为“凭证永不进入沙箱”；或未将vault/代理方案限定为MCP自定义工具，掩盖原文另给的Git资源绑定认证方式。需修订安全边界的表述。
4. OpenAI核心API/工具与短引文成立，但部分笔记省略功能对齐前置条件，或混合正式宣布弃用与目标停用时间。原文是历史计划；不能据此说明今日产品状态。
5. Google通过的笔记保留了自定义函数由客户端执行、后台ID/轮询以及刷新凭证保留沙箱状态等限定。通过的概念节点与摘要依据匹配，链接可解析。

两个OMP任务还在原生参数校验阶段拒绝233字符的引文；初版桥接没计入这两次尝试。完整OMP事件审计后，每次实际5次工具尝试，均未超8，未改变运行结果。统计已校正；扩展现已通过生命周期事件将这类拒绝计入共享预算，离线集成测试覆盖了此情况。

## 实现与复测

- `omp_blog_extension.mjs`：OMP原生注册provider和四个工具，生命周期事件停止成功任务并计入本地参数拒绝。接口依据[18.9.2扩展文档](https://github.com/can1357/oh-my-pi/blob/v18.9.2/docs/extensions.md)。
- `omp_blog_runner.ts`：仅监听127.0.0.1的临时、带随机认证token的适配器；真正的DeepSeek密钥留在父进程，OMP只拿本机token。强制模型、温度、thinking、输出上限及同一工具schema；OMP决定下一步调用什么。
- 原生SSE正文先缓冲到收到usage，再原样交给OMP。计量端到端完成耗时，未比较流式首字延迟。
- OMP使用隔离状态目录；关闭无关工具/规则/Skills、advisor、memory和fallback。测试仅四个已授权工具，写入工具标记为write并在本次CLI中明确自动批准。这个范围限制不是操作系统沙箱，不是通用安全保证。
- `verify_omp_blog.ts`：冻结输入重放、独立真实vault、交替顺序、循环和索引费用拆分、保存hash和内部链接核查。
- `tests/omp_blog_runner.test.ts`：真实启动本机OMP，使用离线模型SSE响应与真实Python工具验证模型/工具循环、无效参数计数、证据核对用量、实际文件保存及成功停止。

在项目根目录配置现有 `.env`，进入 `vercel_agent`：

```sh
# 若没有本机冻结输入，先准备同一批网页快照
npm run verify:blog-workflow -- --prepare
# 使用上一步生成目录的manifest.json；会产生API用量并实际写入测试笔记
npm run verify:omp-blog -- "/absolute/path/to/prepared-directory/manifest.json"
```

比较适配器使用 `~/.local/bin/omp`，以本机18.9.2验证，不承诺跨版本API兼容。该适配器仅用于比较原生循环。后续已另行安装复用固定工作流的日常 `/collect` 命令，见 [OMP_COLLECT.md](OMP_COLLECT.md)。

本轮通过141项TypeScript测试及类型检查；更新后的离线OMP测试再次验证了参数拒绝计数与保存停止。历史24次真实结果没有在修复后覆盖重跑。

本机证据位于 Git 忽略的 `reports/omp-blog/paired-K8zV1w`、`reports/omp-blog/paired-lRjvBE`；最终汇总与逐条审阅在后者的 `comparison-summary.json`、`comparison-reviewed-results.json`。真实笔记位于专属vault的 `OMP对照/<日期>/<批次>/<任务>`。

# 模块 6.3 网页事实表验收

2026-10-07，使用现有 SDK Agent，真实调用 DeepSeek 和 `read_webpage`。没有新增业务工具，也没有调整循环、系统提示词、512 token 输出上限或 0 次接口重试设置。

结论：Agent 可以读取网页并输出带来源的事实表；按预先固定的准确、完整、原文证据标准，两次运行均未完全通过。首轮任务措辞存在歧义，模型选错历史主题；第二轮纠正了主题，但仍有覆盖缺失和引文标点错误。当前证据支持先改善任务定义和验收，而不是立即扩充工具集合。

## 固定任务与标准

来源：[模块 6.3：数据库前传——数据都存在哪儿？](https://xn--ygr25xpohxwz.com/zero-to-fullstack/lessons/module-6-3/)。

输出五行、三列事实表：持久化动机、四种存储、文件局限、数据库范围、历史范围；每行附连续原文短引文，最后附来源 URL。

在调用模型前写入 JSON 的验收标准：

1. 实际读取指定网页，明确读取失败或截断，使用实际来源 URL。
2. 表格格式和五个主题正确。
3. 每行至少一段连续原文引文，逐字可在工具返回的正文中找到。机械匹配只忽略空白，不放宽标点。
4. 持久化动机、内存/文件/数据库/云对象存储四类概括准确。
5. 文件局限必须包含全量读取、全量重写、并发脏写/脏读、半写崩溃损坏四处问题。
6. 数据库部分是事务等机制的铺垫，未展开具体产品和完整原理。
7. 存储历史包含古老记录方式、存储需求先于数据库、最早文字可能为记账；不能概括成只有一句，也不补出完整技术编年史。

任务初始提示只写“历史范围”，未明确区分存储历史与查询记录历史；这是任务定义的缺口。第一次输出后，仅追加一句消歧说明：“历史范围特指‘存储这件事本身的历史背景’，与应用的用户查询历史记录、会话归属无关。”两个变体的验收标准相同，没有向模型提供具体正确答案。

## 人工核对

| 主题 | 首轮 | 消歧后 |
| --- | --- | --- |
| 持久化动机 | 正确：数据留存供运营分析 | 正确：留存查询量、内容和模型准确度等信息 |
| 四种存储 | 四类准确 | 四类准确 |
| 文件局限 | 四处问题均覆盖 | 四处问题均覆盖 |
| 数据库范围 | 基本正确：事务及下一节展开 | 基本正确：事务及下一节用法；概括较简略 |
| 存储历史 | 未回答目标主题；讲的是查询历史的归属和会话 | 已回答古老记录方式和记账假说，但漏掉先有存储需求才有数据库 |

首轮“历史范围”的引文确实存在于原文，内容也可以准确描述用户查询历史；但它没有回答本次要问的存储历史。因此自动检查全部为 true，任务仍未完整通过。这说明引文存在只能验证文字出处，不能证明它回答了正确的问题。

第二轮“历史范围”已包含结绳、泥板、账本、档案柜以及“最早文字或为记账”的限定，未再称历史只有一句。不过，它的“未展开细节”表达较宽泛，更准确应说明未展开完整存储技术发展史；“不含用户查询历史或会话归属”仅能理解为这一行的范围，网页本身实际上讲到了查询历史和会话。如果把它理解为整个网页范围，便是不准确的。

第二轮还漏掉预定标准中的“先有存储需求，才有数据库”，因此覆盖不能记作完全通过。

唯一不匹配的引文是 `这些技术"没有绝对的好，只有合不合适"`。原文尾部使用中文右双引号 `”`，答案改成了 ASCII 双引号 `"`。语义相近，但不符合本次逐字引文要求；没有在看到结果后放宽检查标准。其他十一段引文在忽略空白后的正文中均能找到。

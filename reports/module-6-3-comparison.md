# 指定网页阅读：Codex 与最小 Agent 对比

日期：2026-10-07。

来源：[模块 6.3：数据库前传——数据都存在哪儿？](https://xn--ygr25xpohxwz.com/zero-to-fullstack/lessons/module-6-3/)。

用户的问题：网页讲了什么，以及分别怎样介绍存储、数据库和存储的历史。验收依据是网页原文，Codex 的答案是一个人工核对过的参考答案。

## 本次执行

Codex 通过 ego-browser 读取页面正文和章节目录。首次导航等待 load 超时，但页面已加载到 interactive；在同一浏览器空间继续读取成功。浏览器正文包含复制按钮和前后节链接，共 8432 个字符。

最小 Agent 使用现有系统提示词、四工具注册表、Loop 和本地配置的 DeepSeek 模型；自行选择 read_webpage，没有调用 web_search。Trafilatura 提取正文 8256 个字符，truncated=false。两次运行的工具正文相同，包含全部 10 个二级标题及文章结尾。浏览器与工具的字符数不同，不代表正文被截断。

| 最小 Agent 运行 | 输出上限 | 模型请求 | 工具调用 | tokens | 结果 |
| --- | ---: | ---: | ---: | ---: | --- |
| 当前项目配置 | 512 | 2 | 1 | 7311 | 最终输出 finish_reason=length，框架报告未完成，没有返回半截回答 |
| 临时提高回答预算 | 1536 | 2 | 1 | 7809 | 最终输出 finish_reason=stop，回答完成；最终回答实际使用 1009 completion tokens |

提高上限只发生在复验进程内，未修改 agent.py 的 MAX_OUTPUT_TOKENS。两次调用共使用 15120 tokens。输入正文占主要上下文用量，读取工具本身没有调用模型。

## Codex 的参考回答

### 1. 网页讲了哪些内容？

文章从“文字实验室刷新或重启后丢失结果”出发，介绍持久化需求。接着讲存储的历史、存与取的关系，以及内存、文件、数据库、云/对象存储四种方式。

实际练习重点是用 JSON 文件保存查询记录：记录原文、情感分数、结论、拼音和 created_at；解释为什么朴素的逗号分隔会产生歧义，为什么时间统一存 UTC、展示时再转换。

随后实现 load_history、save_record，让 /api/analyze 写入 history.json，并新增 /api/history 返回最新 10 条记录。通过重启验证数据留存，同时介绍文件操作、异常处理和接口新增字段的演化规则。

最后分析这个文件方案的效率、并发和写入中断问题，引出数据库与事务；提醒当前历史属于全站，区分访客需会话，登录认证则留给后续内容。

### 2. 三个主题分别如何讲解？

| 主题 | 原文的讲解与边界 |
| --- | --- |
| 存储 | 数据留存使运营分析成为可能，也带来保管责任。内存快但随进程结束丢失；硬盘文件能跨重启保存；数据库方便筛选、排序、统计；对象存储适合大文件。选型取决于场景。本节实际实现 JSON 文件持久化。 |
| 数据库 | 重点是解释为什么需要它：当前文件方案取少量记录仍全量读取，增加一条仍整体重写；并发时可能覆盖更新或读到中间状态，写入中断可能损坏整份 JSON。文章以事务引出数据库，具体教学留到下一节；本页没有讲数据库产品、SQL、表结构或索引。 |
| 存储的历史 | 用结绳、泥板、账本、档案柜说明记录和检索需求早于数据库。文章提到文字可能起源于记账，这是文中的概括性说法，没有给出年代、考古依据或完整技术演进史。 |

措辞仍有两处可以更准确：Demo 写“从用户角度无所谓”，原文限定的是文字实验室这类小工具，而且是未必重要；写“本节只讲内存和文件”，更准确的说法是重点实践内存与文件，同时简要引入数据库。这两处是概括时省略限定，不是新增史实或数据库教程。

## 本轮结论

当前默认配置没有完成这项任务，失败点是最终回答预算，不是工具未读到正文。提高回答预算后的复验完成了任务，主要事实符合网页原文，存在上述轻微概括问题。

这说明下一步可以先明确此类阅读任务的回答长度与验收要点。此次没有修改框架、工具或项目默认预算，也没有迁移 SDK。

这是一次实际任务对比，并非同模型、同工具、同上下文的框架对照实验；没有统计 Codex 的模型用量，也不能从这个网页推断其他网页或所有任务的效果。此处核对的是忠实于文章，不是独立验证文章中的全部技术与历史论断。
